= Vulnlog and your scanner
:page-aliases: overview-suppress.adoc

The Vulnlog CLI reads the Vulnlog YAML file and generates suppression files (also called ignore files) for SCA scanners.

Not every reported finding actually affects the project; false positives and findings already mitigated by the project are common.
Suppression files tell the scanner to stop flagging them.
Vulnlog generates one suppression file per scanner so only the reviewed findings are silenced.

image::vulnlog-suppressing.svg[alt="Vulnlog workflow: SCA scanners report findings, the engineer documents the verdict in vulnlog.yaml, and the Vulnlog CLI generates one ignore file per scanner that feeds back to the scanners"]

[#_dependency_check]
=== OWASP Dependency-Check

Vulnlog supports the https://dependency-check.github.io/DependencyCheck/general/suppression.html[OWASP Dependency-Check XML suppression file] format.
With the default `--format auto`, `dependency-check` reports produce `dependency-check-suppressions.xml`.
Only CVE identifiers are supported; other identifier types are skipped.
The entry's analysis becomes `notes`, and `suppress.expires_at`, when set, becomes the exclusive `until` date on the following day.
Each rule applies to the CVE across all dependencies; package and file matchers are not emitted.

[#_generic]
=== Generic

Some scanners (such as Semgrep) have no suppression-file mechanism.
Others (such as Grype) do, but Vulnlog does not yet emit their format.
For both cases Vulnlog writes a generic JSON file that teams can wire into their own tool chain.

You can also request this format for any reporter with `--format generic`, which is useful when you prefer to post-process suppressions in scripts or other tooling rather than use the native format.
