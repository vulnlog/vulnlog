= Verdicts and justifications
:page-aliases: verdicts-and-justifications.adoc
:description: Reference for the verdict, severity, disposition, and justification fields of a Vulnlog entry, and for the states Vulnlog derives from them.

Four fields on an entry record your judgement: `verdict`, `severity`, `disposition`, and `justification`.
Of these, only `verdict` and `disposition`, together with `resolution`, decide the entry's state.

----

----

An entry without `verdict` is `under investigation`.

== Field combinations

[cols="2,1,1,1"]
|===
| `verdict` | `severity` | `disposition` | `justification`

| Not set
| Ignored
| Not allowed
| Ignored

| `affected`
| Required
| Optional
| Ignored

| `not affected`
| Ignored
| Not allowed
| Required
|===

The CLI ignores `justification` without a verdict or with `verdict: affected`, but the JSON schema rejects it.

[[verdict-values]]
== Verdict values

[cols="1,3"]
|===
| Value | Meaning

| Not set
| You're still investigating whether the vulnerability affects your software.

| `affected`
| The vulnerability affects your software.

| `not affected`
| The vulnerability doesn't affect your software.
|===

The CLI rejects `under investigation` as a value of `verdict`.

There is no `fixed` verdict.
An entry records the fix in `resolution`.
See xref:reference/vulnerabilities.adoc#resolution-entry[Resolution].

[[severity-values]]
== Severity values

[cols="1,3"]
|===
| Value | Meaning

| `critical`
| Immediate action required.
Exploitable with severe impact.

| `high`
| Action required.
Significant impact if exploited.

| `medium`
| Action recommended.
Moderate impact.

| `low`
| Low priority.
Minimal impact or difficult to exploit.
|===

[[disposition-values]]
== Disposition values

[cols="1,3"]
|===
| Value | Meaning

| Not set
| You haven't stated what you plan to do.

| `will fix`
| You plan to fix the vulnerability.

| `wont fix`
| You accept the risk and don't plan to fix it.
|===

[[justification-values]]
== Justification values

The values match the justifications of OpenVEX documents, which tell your customers' tools whether a release is affected by a vulnerability.

[cols="1,3"]
|===
| Value | Meaning

| `component not present`
| The vulnerable component isn't part of the software you ship.

| `vulnerable code not present`
| The component is present, but the vulnerable code isn't.

| `vulnerable code not in execute path`
| The vulnerable code is present, but your software never runs it.

| `vulnerable code cannot be controlled by adversary`
| Your software runs the vulnerable code, but an attacker can't trigger the vulnerability.

| `inline mitigations already exist`
| Existing controls, such as input validation or a web application firewall, prevent the attack.
|===

[[states]]
== States

Vulnlog derives a state for each entry from its verdict, disposition, and resolution.
You don't write the state into the file.
The impact report shows it, and its `--state` filter selects by it.

[cols="1,3"]
|===
| State | Condition

| `under investigation`
| No verdict.

| `open`
| `affected`, no resolution, and `disposition` is `will fix` or not set.

| `accepted`
| `affected`, no resolution, and `disposition: wont fix`.

| `resolved`
| `affected` or `not affected`, with a resolution.

| `not applicable`
| `not affected`, no resolution.
|===

With `--as-of`, a resolution in a later release doesn't count.
As of 4.2.0, Log4Shell is `open`, because 4.3.0 fixes it.
For the option, see xref:reference/cli.adoc#filters[Filter options].
For why states work this way, see xref:concepts/vulnerability-states.adoc[Vulnerability states].

== Rules

`vulnlog validate` checks these rules.

[cols="3,1,3"]
|===
| Rule | Level | Message

| `verdict` is `affected`, `not affected`, or not set.
| Error
| `Invalid verdict: fixed`

| An entry with the verdict `affected` has a valid `severity`.
| Error
| `Invalid severity: null`

| An entry with the verdict `not affected` has a valid `justification`.
| Error
| `Invalid justification: null`

| `disposition` appears only with `verdict: affected`.
| Error
| `Disposition requires verdict 'affected'.`

| `disposition` is `will fix` or `wont fix`.
| Error
| `Invalid disposition: maybe`

| An entry with severity `critical` doesn't have `disposition: wont fix`.
| Info
| `A critical severity vulnerability is marked 'wont fix'.`
|===
