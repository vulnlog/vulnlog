= File format
:page-aliases: format-overview.adoc

A Vulnlog file is a YAML document with five top-level keys.
The CLI reads it only under certain file names, and an optional first-line comment links it to the JSON schema.

== Synopsis

[source,yaml]
----
# $schema: https://vulnlog.dev/schema/vulnlog-v1.json
---
schemaVersion: "1"

project:
  organization: Acme Corp
  name: Acme Shop
  author: Acme Product Security Team

tags:
  - id: backend
    description: Java server application

releases:
  - id: 4.2.0

vulnerabilities:

  - id: CVE-2022-42889
    releases: [4.2.0]
    packages: ["pkg:maven/org.apache.commons/commons-text@1.9"]
    reports:
      - reporter: dependency-check
    tags: [backend]
----

== File names

The CLI reads a file only when its name matches one of these patterns:

[cols="1,2"]
|===
| Pattern | Example

| `vulnlog.yaml`
| `vulnlog.yaml`

| `vulnlog.yml`
| `vulnlog.yml`

| `*.vl.yaml`
| `acme-shop.vl.yaml`

| `*.vl.yml`
| `acme-shop.vl.yml`
|===

Any other name fails with `+File name must be [vulnlog|*.vl].[yaml|yml]+`.
You can put the file anywhere in your repository.
You pass its path to every command, because the CLI doesn't search for it.
`-` in place of the path reads the file from standard input.
See xref:reference/cli.adoc#stdin[Standard input and output].

== Schema header

The first line of the file can be a comment that names the JSON schema:

[source,yaml]
----
# $schema: https://vulnlog.dev/schema/vulnlog-v1.json
----

The header is optional.
Editors with YAML schema support use it for validation and completion, and the CLI ignores it.
`vulnlog init` writes the header into every new file.
Commands that write a file keep the header if the file has one, and always write it with the URL shown above.
See xref:guides/set-up-your-editor.adoc[Set up your editor].

== Document start

The document can start with `---`, after the schema header if there is one.
The marker is optional, and `vulnlog fmt` adds it when it's missing.
A file holds one YAML document.

== Top-level keys

[cols="2,2,1,1,4"]
|===
| Key | Type | Required | Default | Description

| `schemaVersion`
| String, `"1"`
| Yes
| None
| Version of the Vulnlog format.
The CLI also accepts `"1.0"` and the number `1`.
A newer version fails with `Unsupported schema version '2'. Try updating vulnlog.`
A value that isn't a version fails with `Invalid schema version 'abc'`.
Without `schemaVersion`, the file fails with `Missing schemaVersion`.

| `project`
| Object
| Yes
| None
| The organisation, project, and author.
See xref:reference/project-and-releases.adoc[Project and releases].

| `tags`
| List of tag objects
| No
| No tags
| Labels you attach to entries and to release package URLs (PURLs).
See xref:reference/tags.adoc[Tags].

| `releases`
| List of release objects
| Yes
| None
| The releases this file tracks.
`vulnlog init` starts with an empty list.
Each entry refers to releases from this list.
See xref:reference/project-and-releases.adoc[Project and releases].

| `vulnerabilities`
| List of entries
| Yes
| None
| One entry per vulnerability.
The list can be empty.
See xref:reference/vulnerabilities.adoc[Vulnerabilities].
|===

== Rules

* Keys that the format doesn't define fail with `Unknown property '<key>'. Try updating vulnlog.`
This applies at every level of the file.
* An empty file fails with `Empty YAML document`.
* The CLI accepts empty lists, such as the `releases: []` that `vulnlog init` writes.
The JSON schema requires at least one item in every list, so an editor that checks the file against the schema marks an empty list.
* The order of `releases` matters.
See xref:reference/project-and-releases.adoc[Project and releases].
* By convention, `vulnerabilities` is listed newest first.
The CLI doesn't check or change this order.
* YAML comments other than the schema header aren't part of the format.
Commands that write the file remove them and print a warning.
The fields for notes are `analysis` and `comment` on an entry, `description` on a tag, and `note` on a resolution.
* Commands that write the file use one canonical style: field order, list style, quoting, and blank lines.
`vulnlog fmt --check` reports where a file differs.
See xref:reference/cli-fmt.adoc[vulnlog fmt].

== Examples

`vulnlog init` writes the smallest file that the CLI accepts:

[source,yaml]
----
# $schema: https://vulnlog.dev/schema/vulnlog-v1.json
---
schemaVersion: "1"

project:
  organization: Acme Corp
  name: Acme Shop
  author: Acme Product Security Team

releases: []

vulnerabilities: []
----
