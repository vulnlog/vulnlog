= Gradle plugin
:page-aliases: gradle-plugin.adoc

The Vulnlog Gradle plugin integrates Vulnlog commands into your Gradle build.

== Installation

Apply the plugin in your `build.gradle.kts`:

[source,kotlin,subs="attributes"]
----
plugins {
    id("dev.vulnlog") version "{vulnlog-version}"
}
----

== Configuration

The plugin is configured via the `vulnlog` extension block.
The top-level `files` property is shared across tasks; per-task settings live in nested blocks documented under each task.

[source,kotlin]
----
vulnlog {
    files.from("vulnlog.yaml", "other.vl.yaml")
}
----

[cols="2,3"]
|===
| Property | Description

| `files`
| File collection of Vulnlog YAML files to operate on. Used by all tasks except `vulnlogInit`.

| `report`
| Container for the report tasks. Each report type has its own nested block: `report { impact { } }` and `report { changelog { } }`.

| `vex`
| Container for the VEX tasks. Each format has its own nested block: `vex { openvex { } }`.
|===

== Diagnostics

The tasks emit the same diagnostics as the CLI's `-v` and `-vv` flags through the Gradle logger.
Run with `gradle --info` to see parsed inputs, validation summaries, filter resolution, written outputs, and skipped suppression entries; `gradle --debug` adds debug detail such as included suppression entries and report entry counts.

== Tasks

All tasks are registered in the `vulnlog` task group.

=== `vulnlogInit`

Scaffolds a minimal Vulnlog file.
See xref:reference/cli-init.adoc[`vulnlog init`] for the generated structure.

`vulnlogInit` is configured via project properties (`-P`) since it is a one-shot bootstrapping command.

[cols="2,1,3"]
|===
| Property | Required | Description

| `vulnlog.organization`
| Yes
| Organization name for the Vulnlog project.

| `vulnlog.name`
| Yes
| Project name.

| `vulnlog.author`
| Yes
| Author name.

| `vulnlog.output`
| Yes
| Output file path, relative to the project directory.
|===

.Example
[source,shell]
----
./gradlew vulnlogInit \
  -Pvulnlog.organization="Acme Corp" \
  -Pvulnlog.name="Widget" \
  -Pvulnlog.author="Alice" \
  -Pvulnlog.output=vulnlog.yaml
----

=== `vulnlogValidate`

Validates the configured Vulnlog files.
See xref:reference/cli-validate.adoc[`vulnlog validate`] for validation rules.

[source,kotlin]
----
vulnlog {
    validate {
        strict = true  // optional
    }
}
----

[cols="2,2,3"]
|===
| Property | Default | Description

| `strict`
| `false`
| Treats warnings as errors and fails the build.
|===

The task uses Gradle's up-to-date checking via `@InputFiles` and `@Input`, so it is skipped when neither the files nor `strict` have changed.

.Example
[source,shell]
----
./gradlew vulnlogValidate
----

=== `vulnlogFormat`

Formats the configured Vulnlog files to the canonical style, rewriting them in place.
See xref:reference/cli-fmt.adoc[`vulnlog fmt`] for the formatting rules.

[source,kotlin]
----
vulnlog {
    fmt {
        check = true  // optional
    }
}
----

[cols="2,2,3"]
|===
| Property | Default | Description

| `check`
| `false`
| Do not write changes; fail the build if any file is not already formatted. Also available as the `--check` task option.
|===

.Example
[source,shell]
----
./gradlew vulnlogFormat
./gradlew vulnlogFormat --check   # CI: fail if any file is unformatted
----

=== `vulnlogSuppress`

Generates suppression files for downstream scanners.
See xref:reference/cli-suppress.adoc[`vulnlog suppress`] for supported reporters.

[source,kotlin]
----
vulnlog {
    suppress {
        outputDir = layout.projectDirectory.dir("suppressions")  // optional
        reporter = "trivy"                                       // optional
        asOf = "1.0.0"                                           // optional
        tags = setOf("frontend")                                 // optional
    }
}
----

[cols="2,2,3"]
|===
| Property | Default | Description

| `outputDir`
| `build/vulnlog/suppressions/`
| Directory where suppression files are written.

| `reporter`
| All reporters
| Filter on reporter.

| `asOf`
| All releases
| Report as of this release, including all releases up to and including it.

| `tags`
| All tags
| Filter on tags.
|===

.Example
[source,shell]
----
./gradlew vulnlogSuppress
----

=== `vulnlogImpactReport`

Generates an HTML impact report from the configured Vulnlog files.
Multiple files are merged and must share the same project metadata.
See xref:reference/cli-report-impact.adoc[`vulnlog report impact`] for details.

Settings live under `report { impact { } }`, so each report type keeps its own block.

[source,kotlin]
----
vulnlog {
    report {
        impact {
            outputFile.set(layout.buildDirectory.file("vulnlog/vulnlog-impact-report.html"))  // optional
            reporter = "trivy"                                                                // optional
            asOf = "1.0.0"                                                                    // optional
            tags = setOf("frontend")                                                          // optional
            states = setOf("open", "accepted")                                                // optional
            verdicts = setOf("affected")                                                      // optional
            dispositions = setOf("wont fix")                                                  // optional
        }
    }
}
----

[cols="2,2,3"]
|===
| Property | Default | Description

| `outputFile`
| `build/vulnlog/vulnlog-impact-report.html`
| File where the HTML report is written.

| `reporter`
| All reporters
| Filter on reporter.

| `asOf`
| All releases
| Report as of this release, including all releases up to and including it.

| `tags`
| All tags
| Filter on tags.

| `states`
| All states
| Filter on xref:concepts/vulnerability-states.adoc[vulnerability state]: `under investigation`, `open`, `accepted`, `resolved`, `not applicable`.
Combined with `asOf`, each entry is reported in the state it was in at that release.

| `verdicts`
| All verdicts
| Filter on xref:reference/verdicts-and-justifications.adoc[triage verdict]: `under investigation`, `affected`, `not affected`.
A verdict is what you recorded, so it does not change with `asOf`.

| `dispositions`
| All dispositions
| Filter on the remediation intent recorded for affected entries: `will fix`, `wont fix`.
Affected entries that state no intent are not selected by either value.
|===

The task is cacheable and uses Gradle's up-to-date checking, so it is skipped when neither the files nor the filter settings have changed.

The task never fails because the report contains vulnerabilities.
It fails the build only on invalid input, for example an unknown `asOf` or input files with different project metadata.

.Example
[source,shell]
----
./gradlew vulnlogImpactReport
----

=== `vulnlogChangelogReport`

Reports which vulnerabilities each release fixed, newest release first.
Multiple files are merged and must share the same project metadata.
See xref:reference/cli-report-changelog.adoc[`vulnlog report changelog`] for the report contents and for what it leaves out.

Settings live under `report { changelog { } }`.

[source,kotlin]
----
vulnlog {
    report {
        changelog {
            outputFile.set(layout.buildDirectory.file("vulnlog/vulnlog-changelog.md"))  // optional
            format = "markdown"                                                         // optional
            brief = false                                                               // optional
            fixedIn = "1.2.0"                                                           // optional
            reporter = "trivy"                                                          // optional
            asOf = "1.1.0"                                                              // optional
            tags = setOf("frontend")                                                    // optional
        }
    }
}
----

[cols="2,2,3"]
|===
| Property | Default | Description

| `outputFile`
| `build/vulnlog/vulnlog-changelog.<ext>`
| File where the report is written.
The default file name follows `format`, so it ends in `.txt` for `text` and `.md` for `markdown`.

| `format`
| `text`
| Output format: `text` or `markdown`.
`markdown` renders one section per release in the Keep a Changelog layout, ready to paste under a heading the changelog file already has.

| `brief`
| `false`
| List identifiers and severity only. Descriptions, resolution notes, and references are left out.

| `fixedIn`
| All releases
| Report only the vulnerabilities this release shipped a fix for.

| `reporter`
| All reporters
| Filter on reporter.

| `asOf`
| All releases
| Report as of this release, including all releases up to and including it.
A fix that ships later is left out.

| `tags`
| All tags
| Filter on tags.
|===

The report holds no timestamp, so the output depends only on the inputs and the settings.
The task is cacheable and is skipped when neither has changed.

The task always writes its output file.
When no entry records a resolution it writes the report for zero releases and logs `info: no fixed vulnerabilities to report`.

It fails the build only on invalid input, for example an unknown `fixedIn` or input files with different project metadata.

.Example
[source,shell]
----
./gradlew vulnlogChangelogReport
----

[#_vulnlogopenvex]
=== `vulnlogOpenVex`

NOTE: The Vulnlog OpenVEX export feature is currently incubating.
Its behavior and configuration options may change in the upcoming releases.

Writes an OpenVEX document from a single Vulnlog file, so Trivy and Grype can drop the findings you triaged.
See xref:reference/cli-vex-openvex.adoc[`vulnlog vex openvex`] for what the document contains.

Settings live under `vex { openvex { } }`.

[source,kotlin]
----
vulnlog {
    vex {
        openvex {
            outputFile.set(layout.buildDirectory.file("vulnlog/vex.json"))  // optional
            release.set("1.2.0")                                            // optional
            tags.set(setOf("container"))                                    // optional
            baseline.set(layout.projectDirectory.file(".vex/app.openvex.json"))  // optional
        }
    }
}
----

[cols="2,2,3"]
|===
| Property | Default | Description

| `outputFile`
| `build/vulnlog/vex.json`
| File where the document is written.

| `release`
| _(none)_
| Write the document for this release only. Without it the document covers every release that declares `purls`.

| `tags`
| _(empty)_
| Keep only the release purls carrying one of these tags.

| `baseline`
| _(none)_
| The committed document to continue. Its identifier is kept and its version counts up when the content changed. The file may not exist yet; the first run then issues a new document. `vulnlogOpenVexUpdate` writes to this file.
|===

The task reads one Vulnlog file, because a document describes the artifacts of one project.
It fails when `files` holds more than one entry.

It also fails when no statement applies, either because no release declares `purls` or because no vulnerability entry references a release that does.
Releases without `purls` are left out of the document and named in a `warning:` line.

`release` and `tags` scope the document exactly as the CLI flags do; see xref:reference/cli-vex-openvex.adoc#scoping[One document per release and artifact].

`vulnlogOpenVex` writes only to `outputFile`, so it can be up to date and taken from the build cache.
`baseline` must not be the `outputFile`, and the build fails when both point at the same path: a task that reads and writes one file is never up to date, and a build cache hit would overwrite your committed document.
Run <<_vulnlogopenvexupdate,`vulnlogOpenVexUpdate`>> to copy the generated document over the `baseline`.

The registered task writes one document.
A VEX document describes one product at one release, so register a `VulnlogOpenVexTask` for each artifact and release you publish:

[source,kotlin]
----
import dev.vulnlog.gradle.VulnlogOpenVexTask

tasks.register<VulnlogOpenVexTask>("vulnlogOpenVexContainer") {
    group = "vulnlog"
    description = "Write the OpenVEX document for the container image of release 1.2.0."
    files.from("vulnlog.yaml")
    release.set("1.2.0")
    tags.set(setOf("container"))
    baseline.set(layout.projectDirectory.file("vex/1.2.0-container.json"))
    outputFile.set(layout.buildDirectory.file("vulnlog/1.2.0-container.json"))
}
----

.Example
[source,shell]
----
./gradlew vulnlogOpenVex
----

[#_vulnlogopenvexupdate]
=== `vulnlogOpenVexUpdate`

NOTE: The Vulnlog OpenVEX export feature is currently incubating.
Its behavior and configuration options may change in the upcoming releases.

Copies the document `vulnlogOpenVex` generated over its `baseline`, so the committed document follows the Vulnlog file.
It runs `vulnlogOpenVex` first and fails when no `baseline` is configured.

[source,kotlin]
----
vulnlog {
    vex {
        openvex {
            baseline.set(layout.projectDirectory.file(".vex/app.openvex.json"))
        }
    }
}
----

The first run creates the `baseline` with a new identifier and `version` `1`.
Later runs keep the file as it is while nothing but the timestamp would change, and count the version up otherwise.
Commit the file after each run that wrote it.

For a task you registered yourself, register a `VulnlogOpenVexUpdateTask` next to it:

[source,kotlin]
----
import dev.vulnlog.gradle.VulnlogOpenVexTask
import dev.vulnlog.gradle.VulnlogOpenVexUpdateTask

tasks.register<VulnlogOpenVexUpdateTask>("vulnlogOpenVexContainerUpdate") {
    group = "vulnlog"
    description = "Update the committed OpenVEX document for the container image of release 1.2.0."
    generatedFile.set(tasks.named<VulnlogOpenVexTask>("vulnlogOpenVexContainer").flatMap { it.outputFile })
    baseline.set(layout.projectDirectory.file("vex/1.2.0-container.json"))
}
----

.Example
[source,shell]
----
./gradlew vulnlogOpenVexUpdate
----

=== `VulnlogCopyTask`

Copies vulnerability entries from a source Vulnlog file into one or more target files.
See xref:reference/cli-copy.adoc[`vulnlog modify copy`] for the underlying behavior, including merge semantics for entries that already exist in a target.

The task type is provided but no task is registered by default, since the source, targets, and IDs to copy depend on the project.
Register a task in your build script for each propagation you want to perform:

[source,kotlin]
----
import dev.vulnlog.gradle.VulnlogCopyTask

tasks.register<VulnlogCopyTask>("vulnlogCopyToBranches") {
    group = "vulnlog"
    description = "Copy a vulnerability analysis into branch files."
    sourceFile.set(layout.projectDirectory.file("source.vl.yaml"))
    destinationFiles.from("target1.vl.yaml", "target2.vl.yaml")
    vulnIds.set(setOf("CVE-2026-002"))
}
----

[cols="2,3"]
|===
| Property | Description

| `sourceFile`
| Vulnlog file to copy entries from.

| `destinationFiles`
| File collection of target Vulnlog files to copy entries into.

| `vulnIds`
| Set of vulnerability IDs to copy. Each ID must exist in the source file.
|===

.Example
[source,shell]
----
./gradlew vulnlogCopyToBranches
----
