= Tags
:page-aliases: tags.adoc

Tags are labels that you define once and attach to entries and to release package URLs (PURLs).
Typical tags name the parts of your software, such as a server, a user interface, or a container image.
Commands filter by tag.
OpenVEX documents, which tell your customers' tools whether a release is affected by a vulnerability, use tags to link entries to release PURLs.

== Synopsis

[source,yaml]
----
tags:
  - id: backend
    description: Java server application

releases:
  - id: 4.3.0
    published_at: 2026-06-15
    purls:
      - purl: "pkg:maven/com.acme/acme-shop-server@4.3.0"
        tags: [backend]

vulnerabilities:

  - id: CVE-2022-42889
    releases: [4.3.0]
    packages: ["pkg:maven/org.apache.commons/commons-text@1.9"]
    reports:
      - reporter: dependency-check
    tags: [backend]
----

== `tags`

`tags` is an optional top-level list of tag definitions.

[cols="2,2,1,1,4"]
|===
| Field | Type | Required | Default | Description

| `id`
| String
| Yes
| None
| Name of the tag.
It can contain spaces, for example `dev dependency`.

| `description`
| String
| No
| None
| What the tag stands for.
|===

== Where you use tags

[cols="2,4"]
|===
| Field | Effect

| `tags` on an entry
| Filters with `--tag` select the entry.
See xref:reference/vulnerabilities.adoc[Vulnerabilities].

| `tags` on a release PURL
| An OpenVEX statement for an entry names the release PURLs that share at least one tag with the entry.
See xref:reference/project-and-releases.adoc[Project and releases] and xref:reference/cli-vex-openvex.adoc[vulnlog vex openvex].
|===

Without `--tag`, commands include every entry, tagged or not.
For the commands that accept `--tag` and how it selects entries, see xref:reference/cli.adoc#filters[Filter options].

An entry without tags gets no OpenVEX statement.
A release PURL without tags appears in no OpenVEX statement.

== Rules

`vulnlog validate` checks these rules.

[cols="3,1,3"]
|===
| Rule | Level | Message

| Each tag `id` is unique.
| Error
| `Duplicate tag ID 'backend'.`

| Each tag on an entry or a release PURL is defined in `tags`.
| Error
| `References undefined tags 'backend'. Defined tags: container, frontend, worker`

| Each defined tag is used on an entry or a release PURL.
| Info
| `Unreferenced tag ID 'backend'.`
|===

A `--tag` value that the file doesn't define fails with `Tag not found`, or with `tags not defined in the file` in `vulnlog modify add`.
For the exit codes, see xref:reference/exit-codes-and-messages.adoc#exit-codes[Exit codes].
