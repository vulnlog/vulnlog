= Glossary
:description: Definitions of the terms the Vulnlog documentation uses, from accepted and analysis to verdict and Vulnlog file.

Accepted::
The state of an entry that is `affected`, has `disposition: wont fix`, and has no resolution.
See xref:reference/verdicts-and-justifications.adoc#states[States].

Alias::
Another ID of the same vulnerability, for example its GHSA ID, listed in `aliases`.
See xref:reference/vulnerabilities.adoc[Vulnerabilities].

Analysis::
The reasoning behind a verdict, recorded in `analysis`.
See xref:reference/vulnerabilities.adoc[Vulnerabilities].

Canonical style::
The one layout in which Vulnlog commands write a Vulnlog file.
See xref:reference/cli-fmt.adoc[vulnlog fmt].

Disposition::
What you plan to do about a vulnerability that affects you: `will fix` or `wont fix`.
See xref:reference/verdicts-and-justifications.adoc[Verdicts and justifications].

Entry::
A vulnerability recorded in the `vulnerabilities` list of a Vulnlog file.
See xref:reference/vulnerabilities.adoc[Vulnerabilities].

Finding::
A vulnerability that a scanner reports.
See xref:concepts/vulnlog-and-your-scanner.adoc[Vulnlog and your scanner].

Generic suppression file::
A JSON suppression file, named `<reporter>.generic.json`, that Vulnlog writes for reporters without a native format.
See xref:reference/suppression.adoc#supported-scanners[Supported scanners].

Impact report::
An HTML page that shows which releases each vulnerability affects, how severely, and its state.
See xref:reference/cli-report-impact.adoc[vulnlog report impact].

Justification::
The reason a vulnerability doesn't affect your software, required with `verdict: not affected`.
See xref:reference/verdicts-and-justifications.adoc[Verdicts and justifications].

Not applicable::
The state of an entry that is `not affected` and has no resolution.
See xref:reference/verdicts-and-justifications.adoc#states[States].

Open::
The state of an entry that is `affected`, has no resolution, and isn't marked `wont fix`.
See xref:reference/verdicts-and-justifications.adoc#states[States].

OpenVEX::
A JSON format for VEX statements.
Vulnlog's OpenVEX output is incubating.
See xref:reference/cli-vex-openvex.adoc[vulnlog vex openvex].

Package URL (PURL)::
A standard identifier for a software package, for example `pkg:maven/org.apache.logging.log4j/log4j-core@2.14.1`.
See xref:reference/project-and-releases.adoc[Project and releases].

Project::
The organisation, project name, and author of a Vulnlog file, recorded in `project`.
See xref:reference/project-and-releases.adoc[Project and releases].

Release::
A version of your software that the Vulnlog file tracks, listed in `releases`.
See xref:reference/project-and-releases.adoc[Project and releases].

Release notes::
A list of the vulnerabilities a release fixes, generated with `vulnlog report changelog`.
See xref:reference/cli-report-changelog.adoc[vulnlog report changelog].

Report::
An item in an entry's `reports` list that names the scanner or source that reported the vulnerability, and when.
See xref:reference/vulnerabilities.adoc#report-entry[Report].

Reporter::
The scanner or other source in a report, for example `trivy` or `other`.
It decides which suppression file the entry goes into.
See xref:reference/suppression.adoc#supported-scanners[Supported scanners].

Resolution::
The release that fixes a vulnerability, recorded in `resolution`.
See xref:reference/vulnerabilities.adoc[Vulnerabilities].

Resolved::
The state of an entry with a verdict and a resolution.
See xref:reference/verdicts-and-justifications.adoc#states[States].

Schema header::
The optional first-line comment that points editors to the Vulnlog JSON schema.
See xref:reference/file-format.adoc[File format].

Severity::
How severe a vulnerability is for your software: `low`, `medium`, `high`, or `critical`.
See xref:reference/verdicts-and-justifications.adoc[Verdicts and justifications].

State::
A label that Vulnlog derives from an entry's verdict, disposition, and resolution.
See xref:reference/verdicts-and-justifications.adoc#states[States].

Suppression::
Listing a finding in a suppression file so that the scanner ignores it, permanently or until a date.
See xref:reference/suppression.adoc[Suppression].

Suppression file::
A file that Vulnlog generates so a scanner ignores a finding, for example `.trivyignore.yaml`.
See xref:reference/suppression.adoc[Suppression].

Tag::
A label you define in `tags` and attach to entries and release PURLs.
See xref:reference/tags.adoc[Tags].

Under investigation::
The state of an entry without a verdict.
See xref:reference/verdicts-and-justifications.adoc#states[States].

Verdict::
Your judgement whether a vulnerability affects your software: `affected` or `not affected`.
See xref:reference/verdicts-and-justifications.adoc[Verdicts and justifications].

VEX::
Vulnerability Exploitability eXchange, a machine-readable statement of whether a vulnerability affects a product.
See xref:concepts/vulnlog-and-vex.adoc[Vulnlog and VEX].

Vulnlog file::
A YAML file in the Vulnlog format, for example `acme-shop.vl.yaml`.
See xref:reference/file-format.adoc[File format].
