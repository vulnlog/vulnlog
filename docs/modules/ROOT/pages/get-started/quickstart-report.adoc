= Read the impact report
:description: Tutorial: read a Vulnlog impact report to see how vulnerabilities affect a project. You don't need to know YAML.

In this tutorial, you read the impact report of the Acme Shop project to find out how vulnerabilities affect it.
You read the team's assessment of each one and see which release fixes what.
It takes about 10 minutes.
You don't edit any file, and you don't need to know YAML.

The impact report is a single HTML file.
It needs no network connection, and you can print it.

== Before you start

* Install the Vulnlog CLI. For instructions, see xref:get-started/install.adoc[Install Vulnlog].
* Have a web browser to open the report.
* Create an empty directory and save the Acme Shop Vulnlog file in it as `acme-shop.vl.yaml`:
+
.acme-shop.vl.yaml
[%collapsible]
====
[source,yaml]
----
include::example$acme-shop.vl.yaml[]
----
====

== Generate the report

In the directory that contains `acme-shop.vl.yaml`, generate the impact report:

[source,bash]
----
vulnlog report impact acme-shop.vl.yaml
----

[source]
----
Wrote: vulnlog-impact-report.html
----

== Open the report

Open `vulnlog-impact-report.html` in your web browser.

image::impact-report.png["The impact report of Acme Shop. The About and Summary boxes are above a table with one row for each of the six vulnerabilities. Select the image to open it in full size.",link=self]

The heading names the report and the project: *Vulnerability Impact Report* for *Acme Shop*.
Below it, you see the organisation, Acme Corp, and the team that maintains the file, the Acme Product Security Team.

== Check what the report covers

The *About* box on the left tells you what you're looking at:

* *Generated* is the date and time the report was created, in UTC.
* *Inputs* is the Vulnlog file the report comes from, `acme-shop.vl.yaml`.
* *Filter* is `none`.

A filter of `none` means the report shows every entry in the file.
A report can also show the state of one release, for example `as of=4.3.0`.
Always check this line before you draw conclusions, because a filtered report leaves entries out.

== Read the summary

The *Summary* box on the right counts the entries:

* *Total* is 6 entries.
* *State* is 1 _Open_, 1 _Investigating_ (the state `under investigation`), 1 _Accepted_, 1 _Resolved_, and 2 _Not applicable_.
* *Open severity* is 1 _Medium_.
* *Accepted severity* is 1 _Low_.

Entries in the state `open` affect Acme Shop and aren't fixed yet, so start with them.
Here, one vulnerability of medium severity is open.

== Read the table

Each row of the table is one vulnerability.
The rows are sorted by state, so `open` entries come first, and entries that don't affect Acme Shop come last.
A coloured bar on the left edge of a row repeats the state, and for `open` entries the colour shows the severity.
Rows for entries `under investigation` and `open` entries without a severity have no bar.

The four columns are:

* *IDs*: the vulnerability identifier, for example `CVE-2022-22965`, and any other identifiers for the same vulnerability below it.
* *State*: where the team stands with the vulnerability.
* *Details*: the team's assessment.
* *Releases*: the Acme Shop releases the vulnerability affects.

Go through the rows from top to bottom:

* `CVE-2022-22965` is _Open_.
The *Details* column shows *Verdict* _Affected_, *Severity* _Medium_, and *Disposition* _Will fix_.
The team confirmed that Acme Shop is affected and plans a fix.
The *Analysis* text explains why the risk is medium.
* `CVE-2023-32681` is _Investigating_.
It has a *Description* but no verdict, because the team hasn't finished its analysis.
Until the team records a verdict, its impact is unknown.
* `CVE-2021-23337` is _Accepted_, with *Disposition* _Wont fix_.
Acme Shop is affected, and the team accepted the risk.
The *Analysis* says why: only administrators can reach the vulnerable function, and the admin interface goes away in Acme Shop 5.0.
* `CVE-2021-44228` is _Resolved_.
Its second identifier, `GHSA-jfh8-c2jp-5v3q`, appears below the CVE.
The *Releases* column shows 4.2.0 and *Fixed in* 4.3.0.
* `CVE-2022-42889` and `CVE-2024-3094` are _Not applicable_.
Their verdict is _Not affected_, and the line in italics under the verdict gives the reason, for example _Vulnerable code not present_.

For the exact meaning of each state, see xref:reference/verdicts-and-justifications.adoc#states[States].

== Answer questions from the report

You can now answer the questions people usually ask about Acme Shop:

* Is anything open? Yes, one vulnerability of medium severity, and the team plans to fix it.
* Is anything still being analysed? Yes, one vulnerability, `CVE-2023-32681`.
* Which risks has the team accepted? One low-severity vulnerability in the admin interface.
* Is Log4Shell (`CVE-2021-44228`) fixed? Yes, in release 4.3.0. Users of 4.2.0 are still affected.

== What you've learned

Now you can:

* Check which entries a report covers before you draw conclusions.
* Read the state of each vulnerability and the team's assessment behind it.
* Answer common questions about a project from its impact report.
