= Install Vulnlog
:page-aliases: installation.adoc
:description: Install the Vulnlog CLI with the install script, Homebrew, or a download, or run Vulnlog in Docker, in GitHub Actions, or in a Gradle build.

Install the Vulnlog CLI on your computer, or run Vulnlog in Docker, in GitHub Actions, or in a Gradle build.
Choose the method that fits where you run Vulnlog.

== Install the CLI

Choose the method for your computer:

[tabs]
======
Install script::
+
--
On Linux and macOS, the install script downloads the latest release and installs it for your user.
It needs `curl` and `unzip`.

. Run the script:
+
[source,console]
----
$ curl -fsSL vulnlog.dev/install | sh
----
+
The script detects your operating system and processor and installs the native binary to `~/.local/bin`.
If `~/.local/bin` doesn't exist, it uses `~/bin`.

. If the script reports that the directory isn't in your `PATH`, add the `export` line it prints to your shell configuration, and open a new terminal.

. Check the installation:
+
[source,console,subs="attributes+"]
----
$ vulnlog --version
vulnlog version {vulnlog-version}
----

Native binaries are available for Linux on x86-64, macOS on Apple silicon, and Windows on x86-64.
On other platforms, the script installs the JVM distribution instead, which needs Java 21 or later.
To install the JVM distribution on a platform that has a native binary, pass `--jvm`:

[source,console]
----
$ curl -fsSL vulnlog.dev/install | sh -s -- --jvm
----

Each release on the https://github.com/vulnlog/vulnlog/releases[Vulnlog releases page] also has the script for that version, `install-vulnlog.sh`.

To uninstall Vulnlog, run the uninstall script:

[source,console]
----
$ curl -fsSL vulnlog.dev/uninstall | sh
----
--

Homebrew::
+
--
On macOS, install Vulnlog from the Vulnlog tap:

[source,console]
----
$ brew install vulnlog/vulnlog/vulnlog
----

To upgrade to the latest release:

[source,console]
----
$ brew update && brew upgrade vulnlog
----
--

Download::
+
--
Use this method on Windows, or when you can't run the install script.

. On the https://github.com/vulnlog/vulnlog/releases[Vulnlog releases page], download the archive for your platform: `vulnlog-linux-amd64.zip`, `vulnlog-macos-aarch64.zip`, or `vulnlog-windows-amd64.zip`.
. Extract the archive.
. Move the `vulnlog` binary (`vulnlog.exe` on Windows) to a directory in your `PATH`.
. Run `vulnlog --version` to check the installation.

For other platforms, download the JVM distribution, `vulnlog-{vulnlog-version}.zip`, from the same page.
It needs Java 21 or later.
Extract it and add its `bin` directory to your `PATH`.
--
======

== Run in Docker

The Vulnlog image is `ghcr.io/vulnlog/vulnlog`.
Each release has an image tagged with its version number.

. Pull the image and check it:
+
[source,console,subs="attributes+"]
----
$ docker pull ghcr.io/vulnlog/vulnlog:{vulnlog-version}
$ docker run --rm ghcr.io/vulnlog/vulnlog:{vulnlog-version} --version
vulnlog version {vulnlog-version}
----

. Mount your project directory at `/work`, the working directory in the container, and run any Vulnlog command:
+
[source,console,subs="attributes+"]
----
$ docker run --rm -v "$PWD:/work" ghcr.io/vulnlog/vulnlog:{vulnlog-version} validate vulnlog.yaml
Validated: vulnlog.yaml
----

The container runs as user ID 1000.
If your user ID is different, Vulnlog can't write files to the mounted directory and reports `permission denied`.
Run the container as your own user to fix this:

[source,console,subs="attributes+"]
----
$ docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/work" ghcr.io/vulnlog/vulnlog:{vulnlog-version} report impact vulnlog.yaml
----

To read a single file without a mount, pass it on standard input with `-i` and use `-` as the file name:

[source,console,subs="attributes+"]
----
$ docker run --rm -i ghcr.io/vulnlog/vulnlog:{vulnlog-version} validate - < vulnlog.yaml
Validated: <stdin>
----

For the commands that read from standard input or write to standard output, see xref:reference/cli.adoc#stdin[Standard input and output].

== Set up in GitHub Actions

Add the Setup Vulnlog CLI action to your job.
It installs the CLI and puts it in the `PATH`, so later steps can run `vulnlog`:

[source,yaml,subs="attributes+"]
----
- name: Set up Vulnlog CLI
  uses: vulnlog/setup-vulnlog@v1
  with:
    version: {vulnlog-version}
----

For the inputs and outputs of the action, see xref:reference/github-action.adoc[GitHub Action].
For a complete workflow, see xref:guides/run-in-ci.adoc[Run in CI pipelines].

== Add the Gradle plugin

In a Gradle build, apply the Vulnlog plugin in `build.gradle.kts`.
Gradle downloads it from the Gradle Plugin Portal:

[source,kotlin,subs="attributes+"]
----
plugins {
    id("dev.vulnlog.plugin") version "{vulnlog-version}"
}
----

You don't need to install the CLI for the plugin.
For its tasks and settings, see xref:reference/gradle-plugin.adoc[Gradle plugin].

== Build from source

You need Git and a JDK to run Gradle.
Gradle downloads the JDK version that the build needs.

. Clone the repository and build the distribution:
+
[source,console]
----
$ git clone https://github.com/vulnlog/vulnlog.git
$ cd vulnlog
$ ./gradlew installDist
----

. Run the CLI from the build directory:
+
[source,console]
----
$ modules/cli-app/build/install/vulnlog/bin/vulnlog --version
----
